# Home Manager — Bluetooth Recovery Dependency Safety Gate

**Status: source-only invariant, not runtime acceptance, radio permission, license clearance, or safe recovery implementation.**

The imported [Bluetooth integration manifest](https://github.com/GoreeCloud/home-manager/blob/main/homeassistant/components/bluetooth/manifest.json) requests bluetooth-auto-recovery==1.6.4, habluetooth==7.1.2 and bluetooth-adapters==2.4.0. The imported constraints preserve these pins and home-assistant-bluetooth==2.0.0; requirements.txt pins home-assistant-bluetooth==2.0.0. This baseline is guarded by [tools/check_bluetooth_dependency_invariants.py](../tools/check_bluetooth_dependency_invariants.py) and eight fake-source-only mutation tests. Future dependency upgrades, dropped recovery references, duplicate constraints or unexpectedly changed import surfaces fail the guard and demand review.

The previously reviewed upstream chain was home-assistant-bluetooth==2.0.0 to habluetooth==7.1.2 to bluetooth-auto-recovery==1.6.4 to PyRIC>=0.1.6.3. The December 2016 GPLv3-only PyRIC 0.1.6.3 source distribution contains Linux networking and privilege-sensitive APIs (raw HCI sockets, fcntl ioctl, rfkill-related code). **Exact runtime reachability, effective permissions, package compatibility, distribution-license duties and device effects remain unverified**. Upstream Bluetooth Auto Recovery 1.6.4 late-imports recovery implementation on a recovery call, but declares PyRIC as an unconditional dependency. Disabling a UI control does not prove the transitive dependency is unnecessary.

The gate examines only four inherited text files using bounded regular-file reads, JSON parsing and exact string pin matching. It **does not** download third-party code, run recovery modules, invoke Bluetooth interfaces, import Home Assistant, access household hardware, resolve the full dependency graph or qualify a wheel. The JSON report deliberately records source-only findings and release_ready=false.

**Next release requirements:** Independently reconcile PyRIC source tags and GPLv3 obligations; review wheel/ABI and Python 3.14.10 dependencies; design a consent-driven user-visible recovery flow that defaults off and executes with least privilege; test denied and failed privileged operations in simulation before any controlled hardware review; validate actual Core startup with a fully reviewed environment; obtain GoreeShield privacy and Wardveil security acceptance. Track [dependency issue #9](https://github.com/GoreeCloud/home-manager/issues/9) and [release issue #1](https://github.com/GoreeCloud/home-manager/issues/1). This document is evidence of unchanged risk, not a completed gate.
